MGT Bookings

Sole developer & owner · v18

A staff-facing restaurant reservation system in active daily use at a busy 13-table restaurant. Full product lifecycle: requirements, data modelling, UI design, deployment, and iterative refactoring.

  • 1,450+ commits
  • 20 tagged releases
  • 3,700+ tests + 310+ rules tests
  • React 19 · Vite
  • Firebase RTDB + Auth
  • Vercel CI/CD
  • Diagnosed two production data-loss incidents, traced them to last-writer-wins clock stamping, and shipped server-enforced compare-and-swap in Firebase security rules, verified by replaying the incident
  • Directed a multi-phase refactor from monolith to modular hooks and components
  • Encoded operational constraints: table-clustering rules, per-cluster capacity, seating-displacement protection
  • Modelled the physical room as configurable data: a drag-and-drop floor-plan editor in centimetres, rendered as a live top-down Plan view with a scrubbable time ruler
  • Designed staff / manager / admin roles with per-person capability overrides, enforced in Firebase security rules as well as in the UI, with a last-admin lockout guard
  • Built a gift-voucher ledger: manual or generated codes that are never reused, partial redemptions, balances that follow the guest to their next booking, and reversals that leave a record
  • Added an admin activity log of every change, with no names stored in log text so a customer's data erasure also erases them from the log
  • Added guest and occasion tags that follow a guest from booking to booking, filter the list, and are erased with the customer
  • Added a schema gate: a device still on an older version stops saving and asks to be refreshed, so it can't overwrite newer data
  • Shipped WhatsApp booking intake parsed by an LLM via serverless functions, with photos, voice notes and PDFs, a monthly cost counter, and the restaurant's WhatsApp Business app sharing the same number; behind an admin module switch, with the test simulator stripped from production builds
